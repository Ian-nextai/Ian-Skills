# 搜索源操作手册

联网动作优先使用环境里的 `web-access` skill，不要直接写死某个商业搜索 API 的账号或 Key。示例中的域名均为保留域名。

## 1. 官方网站 / 官方 API

适合批量获取结构化的展会、协会会员、目录数据。

操作顺序：

1. 打开目标页面，检查 Network 请求和前端脚本
2. 找到公开 JSON API 或静态数据源
3. 记录请求参数、语言参数、分页参数
4. 小批量请求验证字段
5. 再拉取全量，保存到 `raw/` 或 `cache/`

注意：

- API Key 可能写在前端 JS 中。不要把真实 Key 写进 Skill、README、脚本或输出文件。
- 大 `pageSize` 请求可能耗时超过普通命令超时，必要时后台执行。
- 保存原始响应，后续清洗失败时不必重新抓取。

## 2. 搜索引擎 / 网页检索

适合补全企业官网、主营产品、产品线。

推荐查询模板：

```text
"{company}" 主营产品
"{company}" 产品
"{company}" products manufacturer
"{company}" specialized in products
```

中文公司全名效果不好时：

- 用核心字号，而不是完整工商名
- 加入行业词，例如 `轮胎修补`、`汽车电子`
- 避免只搜省份 + 行业，结果会被百科或黄页占据

结果过滤：

- snippet 必须出现公司名或核心字号
- 产品词必须来自配置的产品词典
- 排除地址、电话、注册信息、导航栏、招聘信息
- 多个来源一致时优先保留更具体、更短的产品描述

## 3. 企业官网抓取

按以下顺序尝试：

1. 官方数据中提供的官网链接
2. 搜索结果中的官网链接
3. 邮箱域名对应的网站
4. 企业名称推断的域名，仅作为最后手段

网页内容优先级：

1. 产品页标题 / 产品导航
2. `Products` / `产品中心` 导航文本
3. meta description / keywords
4. 公司简介中的 `专业生产` / `主营` 段落
5. 正文中的产品列表

编码问题：

- 中文老站可能是 GBK / GB18030
- HTTP 头、HTML meta 和实际内容冲突时，以解码后可阅读的中文为准
- 保存原始 HTML 和解码后的文本，便于复核

## 4. 代理

如果环境有可用代理，按工具要求配置。对于 Node.js CLI，常见要求是同时设置：

```bash
NODE_USE_ENV_PROXY=1
HTTP_PROXY=http://127.0.0.1:PORT
HTTPS_PROXY=http://127.0.0.1:PORT
ALL_PROXY=http://127.0.0.1:PORT
NO_PROXY=localhost,127.0.0.1
```

只配置某个工具自己的 `proxyUrl` 可能只代理目标网页，不代理搜索引擎请求。

端口 `%PROXY_PORT%` 仅作占位示例；实际值由用户提供，不要写死在公开 Skill 里。

## 5. 反爬与限流

- 用户代理、区域、语言要和查询匹配
- 并发过高容易触发验证码，先小批量测试
- 出现验证码后暂停，不要继续猛刷
- 一个源连续失败时切换其它源，不要把失败页当成企业信息
- 对同一公司保存查询词、URL、状态码、失败原因，便于审计

## 6. 脱敏

- 不在交付物或公开仓库保留 API Key、Cookie、登录态、内网路径、真实人名、手机号、邮箱、客户名单
- README / Skill / 示例只使用 `example.invalid`、`示例公司` 之类占位
- 搜索结果缓存含第三方个人信息和商业敏感数据时，只保留需要的字段
- 对外发布前检查 `git diff` 和所有新增文件
