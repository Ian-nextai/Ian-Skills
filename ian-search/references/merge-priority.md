# 来源优先级与字段合并

## 核心原则

**先保留权威数据，再补缺口。** 外部搜索结果只有在原字段为空、或原字段明确是低可信推断时才允许覆盖。

推荐优先级：

1. 用户提供的主数据 / 内部数据库
2. 官方活动、官方目录或官方 APIs
3. 企业官网（官网产品 / 导航 / 关键词 / 正文）
4. 企业邮箱域名反查到的官网
5. 搜索引擎或网页检索结果
6. 企业名称关键词推断
7. 分类 / 展区 / 上下文推断

每一行都要同时保存：

- 值字段，例如 `product`
- 来源字段，例如 `product_source`
- 证据链接，例如 `product_link`
- 是否推断，`inferred=true|false`

不要把“推断值”伪装成“查到的值”。

## 缺失值

空白单元格表示原数据没有该项。不要用 `无`、`N/A`、`未知`、空字符串替代品去填满。只有确实提取到有效内容时才写值。

## 名称匹配

按顺序尝试：

1. 完全匹配
2. Unicode NFKC + 小写 + 去标点后匹配
3. 中英文公司名映射匹配
4. 去公司后缀后匹配，例如 `有限公司` / `Co., Ltd.` / `GmbH`
5. 导入名称 / 别名匹配
6. 人工确认的映射表

不要仅凭模糊相似度就覆盖已有企业工商数据。中文简称、英文译名和品牌名容易误合并。

## 字段合并示例

```json
{
  "data": {
    "name": "示例企业",
    "product": "",
    "product_source": "",
    "product_link": ""
  }
}
```

搜索结果确认该企业做 brake pads 后：

```json
{
  "data": {
    "name": "示例企业",
    "product": "brake pads、disc rotors",
    "product_source": "网络检索",
    "product_link": "https://example.invalid/products"
  }
}
```

## 产品字段清洗

- 去掉 `主营产品` / `经营范围` / `Products include` 等前缀
- 保留具体产品词，不保留公司简介、地址、电话、认证、招聘、版权信息
- 去掉明显营销话术和过长句子
- `汽车配件` 这类过泛词不应替代更具体的 `刹车片、刹车盘`
- 多个产品用 `、` 连接，先去重

见 `scripts/common.py` 里的 `accept_product()` 和 `extract_product()`。

## 覆盖规则

只有在满足以下条件时才覆盖：

- 当前字段为空；或
- 当前来源是可信度更低的推断；并且
- 新结果通过产品关键词过滤；并且
- 新结果与公司名称关联（同一 snippet 或页面中出现公司名）；并且
- 新结果不是黑名单中的噪音文本。

## 审计

最终交付前报告：

- 总行数
- 各来源数量
- 覆盖前 / 覆盖后各来源变化
- 抽样 5–10 条变更
- 仍然推断的行数
- 已知失败类型：网站反爬、无可检索产品页、名称歧义等
